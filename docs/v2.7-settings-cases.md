# v2.7 - Settings - design cases

Agreed with David 2026-10-11: *"All of them in, and folder plus saving as
settings -> agreed and agreed on the design with the tool bar icon."*

Gate 1: every case reads "given X, the screen shows Y". Gate 2: each case is a
named test before the code that satisfies it.

## Why it exists

The MCP server needs an on/off switch that works before any figure is open, and
seven options were either fixed in the code or reset on every launch. Nothing in
the app remembered a preference except the panel width and the game's scores.

## The design

- **A Settings button (gear) in the top bar**, at the right end beside Help. It
  opens a card in the same style as Help: every setting, each with one line
  saying what it changes, and **Restore defaults** at the bottom.
- **Stored by the main process**, in `settings.json` in the app's user-data
  folder, so the main process can read the MCP switch itself. The renderer reads
  the file once at start and writes every change straight back.
- **A setting is a PREFERENCE, never part of the record.** Nothing in a project
  file depends on one (tenet 9): the same project opens to the same record on
  any machine.
- **No hidden modes.** A setting that changes what a tool does says so where the
  tool is, not only in the card.

## Cases

### The card
- **S1.** Given the app is open, the top bar shows a Settings button; pressing
  it opens a card listing every setting below, each with its explanation, and a
  Restore defaults button.
- **S2.** Given a setting is changed, it takes effect at once and is still set
  after the app is closed and opened again.
- **S3.** Given the settings file is missing, unreadable, or holds a value out
  of range or of the wrong kind, the app starts with the default for that
  setting and every other setting keeps its stored value.
- **S4.** Given settings differ from the defaults, Restore defaults puts every
  one back, on screen and in the file.

### Starting values for the tools
- **S5.** Given *By colour tolerance* is set to 30, the Auto-extract By colour
  tolerance shows 30 at once and on the next launch. Changing it on the card
  changes it for this session only.
- **S6.** The same for *Flood fill threshold* (Auto-extract) and *Grid removal
  tolerance* (top bar).
- **S7.** Given *Points per traced curve* is 200, a By colour trace or a Flood
  fill records at most 200 points.

### Find lines
- **S8.** Given *Read contour labels* is off, Find lines on a contour figure
  reads no labels and offers none, and the Find lines card says *"Label reading
  is off (Settings)"* instead of promising to read them.
- **S9.** Given *Label confidence* is 0.95, a label read at 90% is refused with
  the reason *"the reader was unsure (90%)"*, exactly as a read below the
  default 0.8 floor is today.

### Export
- **S10.** Given *Export precision* is Full, the Export menu's full-precision
  box starts ticked on every launch; it can still be unticked for one export.
- **S11.** Given *Decimal comma* is on, a CSV export writes `1,5` and separates
  fields with `;`, and a TSV export writes `1,5` with tabs. JSON, LaTeX, MATLAB,
  Python, R and the workbooks are unchanged, because they are code or typed
  numbers. The Export menu shows a line saying so.

### The record
- **S12.** A project saved with any settings holds no setting; opening it with
  the defaults gives the same points and the same export (with the same export
  settings).

### Agents (lands with the MCP server)
- **S13.** The agent settings (*Let agents use PlotTracer*, the folder it may
  open, whether it may save) appear in the card when the server exists, not
  before - a switch that does nothing would be a control that lies.

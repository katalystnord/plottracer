## Tenet 11, both ways

**Prior art (what others did).** No plot digitizer exposes an MCP server; the
"plot" MCP servers that exist all go the other way - they DRAW charts from data.
Desktop apps follow one of two patterns:
- **Inside the running app** - Blender's add-on, the Figma desktop app,
  Electron's embedded server in the main process. The agent's actions happen in
  the window the user is looking at.
- **A separate headless server** - PyGhidra-MCP drives Ghidra's engine with no
  window, from the command line.

The MCP specification itself sets the rules for a local server: stdio or
Streamable HTTP; bind to 127.0.0.1 only; validate the Origin header (DNS
rebinding); authenticate every connection.

**Reverse (what an agent needs to get reliable data out).** An agent cannot
look at the figure the way a person does, so it needs:
1. to SEE the figure - an image of it, with our marks on it, at any zoom;
2. the same prompts and refusals a person gets, as text, so it can recover;
3. what was measured and what was not - the record's roles, places to check,
   refused reads - in every tool result, never only on screen;
4. the export as data, not a file it has to find.

⚑ The agent is **Parallel Universe David's machine cousin**: it can only use what
the tool list and the tool results tell it. A capability no tool description
names does not exist for it. That is gate 4 for an agent.

## The design, as I would build it (for David to agree or change)

- **Inside the running app** (prior art pattern 1). The agent drives the session
  you are looking at; every step it takes appears on screen and is one Undo,
  exactly as if you had done it. You can stop it, correct it, or take over.
  A headless mode (pattern 2) can come later for batch work, on the same tools.
- **Off by default.** A setting, *Let agents use PlotTracer (MCP)*, starts a
  server on 127.0.0.1 only, with a token. The setting shows the address, the
  token and a ready-to-paste configuration for an agent client. Turning it off
  stops the server.
- **Every tool goes through the same model the UI uses**, so an agent meets the
  same guards and the same refusals (tenet 1; "the model has more than one
  entrance").

## Cases

### Connecting
- **M1.** Given the setting is off, an agent connecting to PlotTracer is refused;
  nothing listens.
- **M2.** Given the setting is on, the screen shows the address, the token and a
  configuration snippet; an agent with the token connects, one without it is
  refused, and a request from a browser page (wrong Origin) is refused.
- **M3.** Given an agent is connected, the screen says so (who, since when) and
  offers *Disconnect*.

### Seeing
- **M4.** Given a figure is open, `view_figure` returns an image of it with our
  marks (calibration, lines, places) - the whole figure, or a region at a zoom.
- **M5.** `get_state` returns, as text: the graph type, the calibration step the
  walk is on and its prompt, the series with their point counts and levels,
  and the places to check.

### Doing (the workflow, step by step)
- **M6.** `open_figure` opens an image or a PDF page; `set_graph_type` picks a type.
- **M7.** `calibrate` takes one step at a time - a pixel and, where the prompt
  asks, a value - and returns the next prompt, or the refusal a person would
  get (same words).
- **M8.** `find_lines` takes a colour (or a pixel to take it from) and returns
  what the card says: lines found, gaps bridged, places to check, label reads
  offered.
- **M9.** The corrections: `cut`, `join`, `move_points`, `erase_rect`,
  `set_level` (with its source), `mask_area` - each returns what changed or the
  refusal.
- **M10.** `export` returns the record in a named format (CSV text, JSON) with
  every derived-value column it would carry on disk (Point, Level from).
- **M11.** `undo` / `redo`.

### Honesty
- **M12.** Every result that adds data says what was measured and what was not
  (bridged / shared / interpolated counts, refused reads with reasons, places to
  check). Nothing an agent did is recorded as more certain than the same act by
  a person.
- **M13.** A value the agent SUPPLIES (a calibration value, a typed level) is
  recorded exactly as a typed value is - tenet 9 draws the line between
  measuring and inventing, not between person and agent.

## Open questions for David
1. **Inside the app only for now, headless later** - or both from the start?
2. **Files:** may an agent open any file it names, or only files in a folder you
   choose in the setting?
3. **Saving:** may an agent save projects and exports to disk, or only hand the
   export back to itself (M10)?
4. **Calibration by an agent** (M7, M13): allowed and recorded like a typed
   value - or should the walk ask you to confirm an agent's calibration?

## Tenet 11, both ways

**What it is, in one line:** we have made it possible for an AI to help with
the data extraction in PlotTracer. (David, 2026-10-11: keep the claim that
simple; no comparison with other tools.)

**Prior art (what others did).** Desktop apps that let an agent drive them
follow one of two patterns:
- **Inside the running app** - Blender's add-on, the Figma desktop app,
  Electron's embedded server in the main process. The agent's actions happen in
  the window the user is looking at.
- **A separate headless server** - PyGhidra-MCP drives Ghidra's engine with no
  window, from the command line.

The MCP specification itself sets the rules for a local server: stdio or
Streamable HTTP; bind to 127.0.0.1 only; validate the Origin header (DNS
rebinding); authenticate every connection.

**Reverse (what an agent needs to get reliable data out).** An agent cannot
look at the figure the way a person does, so it needs:
1. to SEE the figure - an image of it, with our marks on it, at any zoom;
2. the same prompts and refusals a person gets, as text, so it can recover;
3. what was measured and what was not - the record's roles, places to check,
   refused reads - in every tool result, never only on screen;
4. the export as data, not a file it has to find.

⚑ The agent is **Parallel Universe David's machine cousin**: it can only use what
the tool list and the tool results tell it. A capability no tool description
names does not exist for it. That is gate 4 for an agent.

## The design, as I would build it (for David to agree or change)

- **Inside the running app** (prior art pattern 1). The agent drives the session
  you are looking at; every step it takes appears on screen and is one Undo,
  exactly as if you had done it. You can stop it, correct it, or take over.
  **Agreed 2026-10-11 (Q1):** no headless mode for now - a person has to be at
  the machine to calibrate (M7).
- **Off by default.** A setting (Settings S13), *Let agents use PlotTracer*, starts a
  server on 127.0.0.1 only, with a token. The setting shows the address, the
  token and a ready-to-paste configuration for an agent client. Turning it off
  stops the server.
- **Every tool goes through the same model the UI uses**, so an agent meets the
  same guards and the same refusals (tenet 1; "the model has more than one
  entrance").

## Cases

### Connecting
- **M1.** Given the setting is off, an agent connecting to PlotTracer is refused;
  nothing listens.
- **M2.** Given the setting is on, the screen shows the address, the token and a
  configuration snippet; an agent with the token connects, one without it is
  refused, and a request from a browser page (wrong Origin) is refused.
- **M3.** *(agreed 2026-10-11)* Given an agent is connected, the screen says so (who, since when) and
  offers *Disconnect*.

### Seeing
- **M4.** Given a figure is open, `view_figure` returns an image of it with our
  marks (calibration, lines, places) - the whole figure, or a region at a zoom.
- **M5.** `get_state` returns, as text: the graph type, the calibration step the
  walk is on and its prompt, the series with their point counts and levels,
  and the places to check.

### Doing (the workflow, step by step)
- **M6.** `open_figure` opens an image or a PDF page from the folder chosen in
  Settings (S13); a path outside it is refused, naming the folder. **The person
  picks the graph type as part of the calibration** (Q5, M7); there is no
  `set_graph_type`. Until the type is picked, data tools are refused with the
  M7 message.
- **M7.** There is no `calibrate` tool; the person calibrates (Q4). Given the
  open figure is not calibrated, every tool that adds or changes data is
  refused with *"This figure is not calibrated yet. Ask the user to pick its
  graph type and calibrate it in PlotTracer, then call get_state."*, and the screen shows the
  calibration walk's first prompt with a line saying an agent is waiting for
  it. Given the figure is calibrated, the agent's tools work; no tool can
  change or remove the calibration, so a recalibration is also the person's.
- **M8.** `find_lines` takes a colour (or a pixel to take it from) and returns
  what the card says: lines found, gaps bridged, places to check, label reads
  offered.
- **M9.** *(agreed 2026-10-11, rewritten by David's correction: "we want the
  agent to also select and place points")* The agent places, selects and moves
  points and uses every correction on the card (cut, join, move to another
  line, delete, set level, mask), through the same model a click goes through;
  a point it places is recorded exactly as a click. Unlike a calibration pixel,
  a misplaced point is wrong only locally and is VISIBLE: every place or move
  returns a close-up crop with the new point marked, so checking is part of
  the step.
- **M9a. The right series, always named.** *(David: "make it easy and obvious
  for the agents to work on the right SERIES of points.")* Every tool that
  reads or changes points takes a required `series` (its id from `get_state`);
  there is no hidden "active series" an agent could be on by accident. A
  missing, unknown or ambiguous series is refused, and the refusal lists the
  series by id, name, colour and point count. Every result names the series it
  acted on. On screen, the series the agent acts on becomes the selected one,
  so you see which line it is working on.
- **M10.** `export` returns the record in a named format (CSV text, JSON) with
  every derived-value column it would carry on disk (Point, Level from), and
  the Settings that shape it (decimal comma, full precision). Writing it, or
  the project, to disk works only with *may save* on (S13), and only inside the
  chosen folder.
- **M11.** *(agreed 2026-10-11)* Each agent tool call is ONE entry on the same
  Undo history you use, in the order the steps happened, whoever made them;
  Ctrl+Z takes back the agent's last step as it does yours. The agent's own
  `undo` undoes its latest step only if that step is still the newest; if the
  user has changed the figure since, it is refused with *"The user has changed
  the figure since your last step; call get_state."* `place_points` takes a
  list, so an agent chooses what is one step.

- **M14.** *(agreed 2026-10-11; David: "With the user being able to click
  approve, continue, inside plottracer." and "It can be more than one step,
  but say perhaps 5 steps, and then give the user a chance to approve, before
  it goes on.")* Two modes, shown and switchable in the connected-agent strip
  (M3); Settings holds the starting mode, default **In rounds**.
  - **In rounds:** the agent takes up to N steps that change the figure
    (Settings, default 5), each applied and visible as it happens, then waits.
    The strip lists the round's steps and offers **Approve and continue**,
    **Undo this round** and **Continue automatically**, inside PlotTracer.
    Undo this round takes back exactly the round's steps (M11) and tells the
    agent *"The user undid your last N steps."* Looking (`view_figure`,
    `get_state`) never counts as a step.
  - **Automatic:** no rounds; **Pause** / **Resume** stop it at the next step
    in either mode.
  - `get_state` reports the mode, the round size and whether the agent is
    waiting. A held call has a bound; past it the agent gets *"Waiting for the
    user; call again to keep waiting."* and the round stays on screen.

#### M14 as observable cases (phase 3, written 2026-10-11 for the build)
- **R1.** Given *In rounds* with round size 5, the agent's first five steps
  apply as they come, each visible; the strip lists the round's steps and
  counts them ("Round: 3 of 5 steps").
- **R2.** Given five steps are done, the agent's sixth step is held, not run;
  the strip says *"The agent has taken 5 steps and is waiting for you"* and
  offers **Approve and continue**, **Undo this round** and **Continue
  automatically**.
- **R3.** Approve and continue: the held step runs, and a new round starts at 1.
- **R4.** Undo this round: exactly the round's steps are taken back, off the
  same Undo history; the held step does NOT run, and the agent is told *"The
  user undid your last 5 steps."* If the user has changed the figure since the
  round's last step, the button is greyed and says so (use Undo instead), so it
  can never take back the user's own work.
- **R5.** Continue automatically: the mode becomes *Automatic*, the held step
  runs, and nothing is held again until Pause.
- **R6.** Pause, in either mode: the agent's next step is held; the strip says
  it is paused and offers **Resume**.
- **R7.** Looking is never a step: `get_state`, `view_figure`, `list_folder`,
  `list_points`, `select_points` and `export` neither count nor wait.
- **R8.** A held call answers after 60 seconds with *"Waiting for the user; call
  again to keep waiting."*; the round stays on screen and a new call waits again.
- **R9.** `get_state` says the mode, the round size, the steps taken this round,
  and whether the agent is waiting or paused.
- **R10.** Settings ▸ Agents holds the starting mode (default *In rounds*) and
  the round size (default 5), under the switch; the strip switches the mode for
  this connection.
- **R11.** A new connection starts a fresh round in the starting mode.
- **R12** (David, 2026-10-12). Opening another figure starts a fresh round: the
  strip shows no steps, and a step held at that moment is not taken - the agent
  is told the user opened another figure and to call get_state.

### Honesty
- **M12.** Every result that adds data says what was measured and what was not
  (bridged / shared / interpolated counts, refused reads with reasons, places to
  check). Nothing an agent did is recorded as more certain than the same act by
  a person.
- **M13.** A value the agent SUPPLIES (a typed level) is recorded exactly as a
  typed value is - tenet 9 draws the line between measuring and inventing, not
  between person and agent. Calibration is the exception (M7): every value in
  the figure rests on it, a misplaced reference pixel shifts all of them the
  same way and nothing downstream can see it, and an agent's pixel placement
  is unmeasured.

the switch in Settings, the connected-agent strip.

**Phase 2 (doing, M6-M13), 2026-10-11.** The tools, in the order `tools/list`
gives them: `get_state`, `view_figure`, `list_folder`, `open_figure`,
`add_series`, `rename_series`, `remove_series`, `list_points`, `place_points`,
`place_guide_points` (added 2026-10-12), `move_point`, `select_points`, `delete_points`, `cut_line`, `join_lines`,
`move_to_line`, `set_level`, `use_label_read`, `find_lines`, `mask_area`,
`export`, `undo`.
Tests: `ui/src/__tests__/agentDoing.test.ts` (the cases, over a real session),
`ui/__tests__/electronMcp.test.ts` (the folder rules), and the walkthrough
*M6-M11 an agent opens a figure from the chosen folder…* in
`ui/__tests__/workspace.e2e.test.ts`.

Calls I made while building it, for David to confirm or change:
- **Series and points are counted from 1, as the screen counts them.** The
  table and the point labels say 1-9; a tool that said 0-8 would make the agent
  and the person mean different points by the same number.
- **Five tools the cases did not name, because an agent could not do the work
  without them:** `list_folder` (what M6 may open), `add_series` /
  `rename_series` / `remove_series` (one series per curve, named as the legend
  names it; and clearing the stray pieces Find lines found on another line),
  `list_points` (the numbers every point tool takes).
- **`open_figure` is refused while the user has unsaved work**, where a person
  would be asked to confirm. An agent never discards the user's work.
- **Saving never writes over an existing file.** The agent is told to pick
  another name.
- **`list_folder` also looks two folders down** inside the chosen folder.
- **`export` gives every series unless one is named**, and says which it holds.
  The Export menu's Active / All choice is the person's; the agent says what it
  wants instead.
- **An agent's selection switches the tool to Select**, because a selection is
  drawn and kept only there.
- **A label read Find lines offers is shown to the agent in its series line**,
  and `use_label_read` takes it exactly as the Use button beside the Level does:
  recorded as read from the label (measured), never as typed (M12, M13).
- **`open_figure` takes a page** for a PDF or multi-page TIFF, and answers only
  once that page is on screen, naming it ("page 2 of 3").
- **Find lines run by an agent opens the Find lines card** with the colour it
  used, so the card shows what the agent asked for and what came back.
- **`place_guide_points` is Auto-extract ▸ Guide points** (added 2026-10-12,
  David: *"that is the right tool for a job like this, so it needs to be
  exposed"*): the guide points are clicks, the curve between them is
  PlotTracer's spline, and the reply says the in-between points come from that
  curve, not from the ink. Refused on a type whose card does not offer it.
- **A tuple type is counted in its own record** (2026-10-12): "4 bars (8
  clicks)", not "8 points", and `place_points` there answers with the record as
  exported rather than a value per corner. A heatmap's series line says its
  record is its cells.

Measured on one drive (2026-10-11, `xy-multiseries-modulus`, an agent placing
Blend A's nine markers by eye from `view_figure` and tracing Blend B with
`find_lines`): largest error against the truth file 0.17% of the Y axis span for
the placed points and 0.28% for the 217 traced points - one to two pixels.
A second drive (`contour-potential-energy`, the person picking Contour and
calibrating, the agent running `find_lines` then `use_label_read` on all seven
lines): every level matched the truth file, and every traced point lay within
1.7 pixels of the truth line of its own level (mean 0.3).

**Phase 3 (rounds, M14 / R1-R11), 2026-10-11.** `ui/src/agent/agentRounds.ts`
is the gate, tested in `ui/src/__tests__/agentRounds.test.ts`; the strip holds
the mode switch (*In rounds of N* / *Automatic*), Pause / Resume, the round's
steps in words, and Approve and continue / Undo this round / Continue
automatically. Settings ▸ Agents gains *An agent starts* (In rounds /
Automatic) and *Steps in a round* (default 5). Walkthrough: *M14 R1-R10 in
rounds the agent waits after its round…*.

Calls made while building it:
- **A complete round is offered for approval at once**, as soon as its last
  step lands, rather than only when the agent asks for the next one.
- **The round lists its steps in words** ("Placed 9 points in "Blend A"",
  "Found lines of colour #c0392b"); the agent's own undo answers in the same
  words.
- **Undo this round is refused, with the reason on screen, once the user has
  changed the figure since the round's last step**, so it can never take back
  the user's own work (Undo in the top bar still can).
- **A step the agent undoes itself leaves the round**; opening a new figure
  starts a fresh round, since the old round's steps were on the old document.
- **An Undo this round the agent was not waiting on is told to it once**, at
  the head of its next `get_state`, or as the refusal of its next step.
- **Looking does not wait behind a held step** (`get_state`, `view_figure`,
  `list_points`, `select_points`, `export`), so a waiting agent can still look.
- Checked on the real app: a held call answered after 60 seconds with "Waiting
  for the user; call again to keep waiting.", and the round stayed on screen.

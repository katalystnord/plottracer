# v2.7 workflow walk (from 2026-10-30)

David walks the workflow step by step in the built app; each step records what did not work and what should
change, in his words where possible. Only his decisions are written here. The rules it is held to (David,
2026-10-21): automatic tools live inside the existing cards and tools and produce the same objects the manual
way does; manual and automatic steps mix seamlessly. And (David, 2026-10-31): **one workflow and one UI layout
for every kind of figure** (drawn PDF, PDF page as a picture, PNG, JPEG, scan); whatever is settled holds for all of
them. (Later, not now: "PDF" becomes PDF + SVG.)

⚑⚑ **There is no separation between an automatic and a manual flow** (David, 2026-10-31: "This is really important
that you see this"). There is one card per step and, in it, ways of doing the step: a click, the guided order,
a detection. Each produces the same objects, any of them can finish or correct what another started, and nothing
records which one was used. Never write "the manual walk" or "the automatic path" as if they were two things.

## Step 3: the calibration card (the final design, David 2026-10-31)

- Just under the card's header (the fold arrow and "Calibration"), a new button: **[Automatic axis detection]**.
- After the calibration has been set, clicking the calibration tool on the left rail (the second button, the
  crosshair) unfolds the calibration card.
- If a calibration point is moved, the chart loses its calibration, and the user clicks Calibrate again, which
  closes the card. Every move counts, a one-pixel arrow-key nudge as much as a drag: "To be consistent."
  And every other change to the calibration too (David, 2026-11-01): editing a point's typed value, or an option
  such as Log X. (Until now each of these re-calibrated live.)
- While the figure is Not calibrated, the data table keeps its rows and greys out the values (David,
  2026-11-01: "just greying out the values"); Calibrate brings them back in full. (Until now the table showed no
  rows at all until Calibrate.)
- Pressing [Automatic axis detection]:
  - if no points can be found, a warning in the lower information bar says that no calibration points could be
    fixed (David's word), with the warning triangle, as every can't-go-on message;
  - every calibration point that can be detected is placed, and left there for the user to adjust if needed;
  - each detected point comes with its number, read from its label (X1 on the tick under "1000" comes with 1000
    filled in); both the point's placement and its number stay editable by the user;
  - detection works on the assumption that X1 and Y1 share a point (Common origin), so it places the origin,
    X2 and Y2. Settled (David, 2026-11-01, "Yes, C."): the origin is shared only when the corner where the axes
    meet is labelled on both axes; otherwise X1 sits on the first labelled X tick and Y1 on the first labelled Y
    tick, as two points. Every number detection fills in is one printed on the figure, never one worked out;
  - a point that was not found can still be placed: the user clicks its chip in the calibration card (X2, say),
    then clicks the canvas.
- Clicking a chip and then the canvas places that point at any time, with or without a detection: "yes of course."
- The calibration card is the Calibrate tool's fold-out, detached from the rail so it is always visible, at least
  folded: calibration is the crucial first step and the user must see whether the figure is calibrated. The
  multi-figure arrows stay on either side of it. Card and tool are linked both ways (David, 2026-11-01): opening
  the card makes Calibrate the active tool, and leaving Calibrate folds the card.
- Calibration handles can be selected and moved only while the card is open. If the card covers one, the user
  pans: "a user can always pan or move the graph to see all the points in a graph."

### The data area, apart from the calibration (David, 2026-11-01)

- The data area becomes a rectangle of its own: set by detection, adjustable by the user. Until now the area
  Colour trace starts from and Find lines searches was the box round the calibration points (`calibrationBoxRegion`,
  ours since 2026-07-22, not WPD's: WPD searches a region the user marks, or the whole image). Option C put the
  points on the outermost labelled ticks, inside the frame, so that box no longer covers the data.
- Calibration is set on the tick marks for every axis, on every graph type that is XY in some form (David: "we
  need to set calibration on the tickmarks for every axis, for all types of graphs which are XY type graphs in
  some form"). Checked in `engine/axesTypeConfigs.ts`, those are XY, Contour, Histogram, Heatmap, Bar, Line,
  Box plot, Candlestick, Stacked bar and Span chart; not Polar, Ternary, Pie, Spider or Circular chart recorder.
- A new model (David, 2026-11-01): at least two tick marks on every value axis, and two tick marks on a category
  axis as well, "to be sure we have the coordinates right" (today Cat 1 and Cat n are the outer edges of the first
  and last category). Open: whether the data area is limited at all, and if so whether by a 2- or 3-point
  rectangle.
- Settled (David, 2026-11-01, "build and try this"): the data area is a two-corner search area for the automatic
  tools only; it never stops a point placed by hand and never cuts the record. [Automatic axis detection] sets
  it (ChartDete's plot area on a picture, the drawn frame on a PDF); calibrated by hand, it defaults to the whole
  image, as in WPD. And it "has to be reflected in the manual workflow as well": the user can set it by hand too.
  Then follows the required step of setting the tick marks for calibration.
- The walk (David, 2026-11-01): "You no longer click the extremities first. First you do a click drag for the data
  area. And then set the tick marks for value calibration."
- Built (v2.7, `engine/dataArea.ts`), as cases:
  - Given a captured figure of an XY-family type with no data area and no point placed, the calibration card's
    first row is the **Data area** chip, highlighted, saying "drag on image", and the tips bar says "Mark the data
    area: drag a box from one corner of the plot to the opposite corner. The automatic tools search inside it." A
    click places nothing; a drag records the rectangle, outlined in green and labelled "Data area", and the walk
    moves to X1.
  - Given a data area, its four square grips can be dragged while the calibration card is open, and not once it is
    folded. A plain click on a grip is a click on the figure there, so X1 on the frame's corner still places X1
    (found by the tests: the grip swallowed that click).
  - Given the Data area chip picked again, the drag is asked for again and the new rectangle replaces the old.
  - Given [Automatic axis detection], the data area is set to the frame: on a drawn PDF the frame the drawing holds
    (a rectangle round the read ticks, or two axis lines meeting at a corner; checked to 1.5 px against matplotlib,
    R base, R cairo, ggplot2 and LibreOffice, including frames past the last label); on a picture the frame found
    near ChartDete's plot area (the bundled modulus figure: within 3 px of its frame, X 0 to 110 where the labels
    stop at 100). It is set even when no calibration point could be fixed.
  - Colour trace starts from the data area and Find lines searches it; with none marked, both use the whole image.
  - It is saved with the project, undone and redone, turned with the picture, and cleared by Reset calibration.
- Claude's choices, for David to confirm: marking or moving the data area does NOT lose the calibration (it is not
  the scale); picking another chip skips the data area and it is not asked for again until its chip is picked;
  Calibrate does not require it.
- Measured 2026-11-02 (the app's own `findLines` and `runColorTrace` on the bundled samples, colour taken off the
  first series; the frame from each sample's truth file against the whole image, which is what a figure calibrated
  by hand with no data area gets):

  | Figure | Find lines, frame | Find lines, whole image | Colour trace, whole image |
  |---|---|---|---|
  | xy-multiseries-modulus | 15 lines, 0 points outside the frame | 81 lines, 2062 points outside | 0 of 500 outside |
  | xy-stress-strain | 1 line, 0 outside | 30 lines, 1483 outside | 0 of 500 outside |
  | xy-dashed-release (black ink) | 31 lines, 0 outside | 44 lines, 578 outside | 114 of 500 outside |
  | contour-potential-energy | 7 lines, 0 outside | 20 lines, 215 outside | 122 of 500 outside |

  So with no data area, Find lines takes the labels, title and axes for lines on every figure tried, and Colour trace
  does where the series shares the axes' ink. The WPD default (whole image) works against both tools here; whether
  the data area should then be required before they run is a question for David.
- The tick-mark step, value axes (built 2026-11-01 night): given any XY-family type except the heatmap, each value
  step's prompt asks for a labelled tick mark and the number printed there ("Click a labelled tick mark on the X axis
  and enter the number printed there"; the second "with a different number"), on X/Y, a bar's value axis (P1, P2) and
  a line chart's Y (V1, V2). Enforced by `engine/__tests__/valueTickPrompts.test.ts`.
- Not built, open for David:
  - the category axis on two tick marks: Cat 1 and Cat n are still the outer edges of the first and last category.
    Checked in the code: the category axis already carries a "ticks at" convention (`TickConvention`, centred or
    edge, default centred), chosen in the Categories stage AFTER calibration. Reading Cat 1 and Cat n as ticks needs
    that choice made before (at a centred tick the outer edge is half a spacing further out), so where the choice is
    asked, and its default, are David's;
  - the heatmap's walk (its corners "where the first column meets the first row") is unchanged, for the same reason;
  - whether the category axis's direction is measured from its two ticks or assumed at 90 degrees (Claude suggested
    measured, as X and Y are).
- On every value axis at least two tick marks; on a category axis two tick marks as well (plus the count), its
  direction measured from them as X's and Y's are, not assumed at 90 degrees (Claude's suggestion; David asked).
- Measured in matplotlib 3.10: the frame is the data's extent plus a margin (5%; ggplot2 adds 0.6 of a category on
  a discrete axis), set apart from the ticks; category ticks sit at the category centres on bar, box plot and
  seaborn heatmap; the "outer edge of the first category" is often drawn nowhere (bar: edge at -0.4, frame at
  -0.59).
- Prior art (tenet 11): WebPlotDigitizer and Origin's Digitizer both keep the scale apart from the area automatic
  extraction searches; Engauge has no area at all. Reverse: a plotting library sets the frame (`xlim`/`ylim`)
  apart from where the ticks go.

- **3 Legend**, a new rail button folding out three tools: Mark the legend · Automatically detect legend · Mask an

- The Eraser erases whatever is selected, OR whatever it is clicked on. (Today, checked in the code: a click
  removes that data point; a dragged box removes every line's points inside it, on Find lines' graph types only;
  a selection is deleted with Del, not the Eraser. So erasing the selection is new.)
  Settled (David, 2026-10-31, "yes!"): the Eraser erases what it touches, and a selection counts as one thing.
  - Clicking a point that is part of the selection erases the whole selection, in one undo.
  - Clicking any other point erases just that point, as today.
  - A dragged box erases everything inside it, on every graph type (today only on Find lines' types).
  - Del still deletes a selection without the Eraser.
  - Picking the Eraser alone erases nothing.
- The groups: 0-3 (Pan, Edit image, Calibrate, Legend) are one group; 4-6 + Eraser (Data extraction, Select,
  Error bars, Eraser) the next; then 7 Measure, 8 Curve fit, 9 Geometry. With three tools merged into one, every
  tool keeps a number key.

## Step 3b: tick marks (David, 2026-10-31)

- A fold-out section at the bottom of the calibration card, in the same place on every graph.
- Graphs that need it (category axes: bar, histogram, heatmap): a required second step, unfolding by itself once
  the calibration is set. It holds today's Categories stage.
- Graphs that do not (value axes): the section is shown in its place, GREYED OUT, and cannot be unfolded, because
  on a value axis tick marks do nothing for now ("the honest answer is nothing for now"). It stays in the layout
  because a graph type nobody has dreamt up yet may need non-exact but still value-based tick points; it ungreys
  for that type only.

## The Legend tool's card (rail 3, David 2026-10-31)

Only three buttons, top to bottom: **[Mark legend]**, **[Auto detect legend]**, **[Mask an area]**.

- Nothing that is read from the legend is shown to the user ("It will just confuse people"). What is read is
  used only to offer series names as suggestions, and by the internal tools to help the automatic series
  detection.
- The only thing shown is the legend's corners, whether marked or auto-detected.
- Everything developed toward this comes into the workflow branch (David, 2026-11-01: "we need to bring in
  everything that we have developed that is part of solving this. I do not care where it is stored."): ChartDete
  and the graph-type classifier in the app's runtime, picture axes with labels lead, label vetting, the tick
  finder, the warning triangle. The separate automatic path's cards stay behind (2026-10-21).
- A marked or detected legend is masked by itself: "that is half the point." Mask an area stays for everything
  else that is not data (text, arrows, insets, reference lines). Marking the legend by hand is the same
  corner-to-corner drag as Mask an area and crop.
- A masked area and a marked legend are shaded in different colours, so they can be told apart.
- A mask no longer paints the area out of the picture (David, 2026-11-01: "then we change this of course"). A
  masked area and the legend are rectangles laid over the figure: the picture stays as it was, every reader sees
  the rectangles blanked out, and each keeps its corners, editable while the Legend card is open.
- If Auto detect legend finds nothing, a warning with the triangle in the bottom bar says so, as the calibration
  card's detection does.
- Selecting a legend corner lets the user edit it while the Legend card is open; with the card closed it cannot
  be selected or changed. The same as the calibration card.

## The Data extraction card (rail 4, David 2026-10-31)

Started fresh: Place point, the Auto-extract card and the Series extraction card are retired as presentations
(built on old workflows and concepts); their components are reused underneath. The card, as David settled it:

```
▼ Data extraction
Into: ■ w0 = 2            (the series picked in the Series panel; no second picker)

[Auto-extract all series]
Reads every series the legend names, each with the tool that suits it.

Find individual series
[Find lines] [Colour trace]
[Fill a region] [Follow guide points]

Trace by hand
[Place points]

[Split a line]
```

- [Auto-extract all series] has the only explanation line; the other tools are explained by the tips bar when
  picked. If it cannot read anything at all, the same warning with the triangle in the bottom bar as the other
  automatic tools. (The explanation's wording is Claude's, for David to correct.)
- Fill a region is today's Segment fill; Follow guide points is Interpolate; Split a line is Cut.
- A tool that does not apply to the graph type is greyed in its place.
- When the card opens, no tool in it is picked; the user picks one (David, 2026-11-01: "Should we not leave this
  up to the user to pick? Because it depends on the type of graph."). Until then a click on the figure adds
  nothing. This holds on every graph, also where only one tool applies (box plot, candlestick, pie, line with
  categories): "Let the user pick, even if it is only one."
- Calibrate opens nothing after it (David, 2026-11-01, settled before): the user may want to mark the legend first,
  or may not. Calibrate folds the calibration card and that is all; the next tool is the user's choice. Until v2.7
  a successful Calibrate also switched to Add points; that goes, "because the user now has one of two choices:
  either legend or data as next step."
- A heatmap's grid and Read cells stay on the calibration card, as its second stage (David, 2026-11-01: "it needs
  to live there, because it is part of detecting the tick points"); the grid's boundaries are its tick marks, the
  section of step 3b. So on a heatmap every tool in the Data extraction card is greyed.
- Places to check stays in the right panel below the data, not in the card (David, 2026-10-10).
- **As narrow as possible**: extra height is better than width; buttons may stack under each other and change
  order to keep it narrow.

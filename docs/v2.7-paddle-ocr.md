# v2.7: Tesseract is replaced by PaddleOCR

Status: built on branch `v2.7-paddle-ocr` (worked from beast) and merged into `v2.7` on 2026-10-16.
Decided by David on 2026-10-15.

## Why

Measured on CHART-Info 2022 PMC test splits 4 and 5 (887 real charts), same crops as
`plottracer-benchmarks/harness/score-ocr.mjs`:

| Reader | Horizontal tick labels exact (12,751) | Same, tall crops also tried rotated |
|---|---|---|
| Tesseract, as shipped (eng 4.0.0_best_int, LSTM) | 79.8% | 83.9% |
| PP-OCRv6 tiny rec (4.5 MB) | 89.6% | 94.6% |

Legend entries (1,641, same pixel rule, only the text boxes differ): PaddleOCR finds 1.5 to 3 times as
many and reads 82% of found labels exactly, against 58% for Tesseract.

PP-OCRv6 tiny also has the characters Tesseract eng lacks: å ä ö, Greek, µ, °, ±, superscripts.

## Shape of the change

- `ui/electron-ocr.cjs` keeps its interface (`readText(base64Png)` returning text, confidence or error,
  `shutdownOcr()`), so callers do not change.
- Engine: the PP-OCRv6 tiny recognition model converted to ONNX, run by `onnxruntime-web` (wasm) in the
  main process. About the same shipped size as Tesseract (about 19 MB raw against 16 MB; about 6 MB
  compressed either way). Measured in Node: 6.6 ms per label.
- Files that will change: `ui/electron-ocr.cjs`, `build/electron-builder-ui.yml` (the OCR allow list),
  `package.json` / `package-lock.json` (tesseract.js out, onnxruntime-web in), licence and About
  attribution, the OCR tests under `engine/__tests__/ocr*.test.ts` and `ui/__tests__/packagedApp.e2e.test.ts`.

## For work on v2.7 meanwhile

Please leave the files above to this branch where possible. Anything that calls `readText` can carry on
unchanged. Licences checked: PP-OCRv6 models and PaddleOCR Apache-2.0, onnxruntime-web MIT.

## Plan (agreed 2026-10-15, written before any code)

What the code survey found, and why the change is bigger than swapping one model:

- The live category path (`readBandAtAngle`) reads a whole BAND in one call and needs WORD boxes back
  (`wordsToTicks` files each word under its tick) plus a confidence for the angle sweep. So PlotTracer
  needs PP-OCRv6 tiny DETECTION (2 MB) as well as recognition, with the DB post-processing written in JS.
- Paddle returns LINES ("2 3 4 5 ... 19" came back as one box on a real chart). Words are recovered from
  the recogniser's own per-character positions (CTC time steps), so each word keeps its own box.
- `readText` takes PNG bytes. Tesseract decoded them itself; ONNX Runtime does not, so the main process
  gets a small PNG decoder (node `zlib`, 8-bit, non-interlaced, which is what `canvas.toDataURL` makes).
- Confidence stays on the 0 to 100 scale callers already use (`ocrOffline` expects over 50,
  `readLabelCrop` divides by 100).
- ⚠️ Touches the line-finding area in one place: `MIN_CONFIDENCE = 0.8` in
  `algorithms/findLines/labels.ts` was chosen on Tesseract's confidences (READS-dev.md in
  plottracer-ref). Paddle's scores are calibrated differently, so it is re-measured on the same dev set
  and changed only with that table as the evidence.

## Cases (each one a named test; "given X, the screen or the reader shows Y")

Kept from the Tesseract suite, unchanged in what they demand:
1. Given the network removed, reading `label-flax.png` answers `Flax` with confidence over 50.
2. Reading a label leaves no file anywhere on disk.
3. Given a read that cannot finish in time, the answer is a refusal sentence, not a hang.
4. Given bytes that are not an image, the answer is a refusal sentence and the process lives.
5. Given one band drag on `bar-tensile-strength`, all six category names are proposed.
6. Every shipped figure's category names read at or above their per-figure floors (34 of 36 per label).
7. The whole-band, one-angle read holds its floors (42 of 44).

New:
8. Given a label written `Hållfasthet`, `µm` or `°C`, the reader answers it exactly (Tesseract eng could not).
9. Given a band whose labels the detector returns as ONE line, each category still gets its own word and
   its own name.
10. The packaged app reads `label-flax.png` from a tree with no Tesseract files in it.
11. Help ▸ About and README name PaddleOCR / PP-OCRv6 (Apache-2.0) and ONNX Runtime (MIT), say the model
    was converted to ONNX, and no longer name Tesseract; the licence texts and ONNX Runtime's
    ThirdPartyNotices ship in the package.
12. Contour labels: re-run READS-dev with the new reader; the threshold comes from that table, and right
    reads do not fall below Tesseract's 48 of 121.
13. Benchmark: `plottracer-benchmarks` `score-ocr.mjs` through the shipped `readText` reaches at least 89%
    on PMC splits 4 and 5 (Tesseract 79.8%).

Order: model files and the conversion script; cases 8 and 9 written red; the reader; the existing suite
green; packaging and case 10; attribution (11); contour threshold (12); benchmark (13); rebuild the .deb
for David to try.

## Measured during the build

Case 12, contour labels (`plottracer-ref/research/v2.6-findlines-port`, LABELS=1, both readers run
with the harness as it stands on 2026-10-15; right / wrong at each confidence floor):

| floor | dev Tesseract | dev Paddle | heldout2 Tesseract | heldout2 Paddle |
|---|---|---|---|---|
| 0.00 | 58 / 67 | 84 / 41 | 47 / 75 | 79 / 43 |
| 0.70 | 56 / 34 | 84 / 27 | 47 / 44 | 79 / 27 |
| 0.80 | 51 / 25 | 84 / 21 | 42 / 37 | 78 / 26 |
| 0.85 | 51 / 20 | 84 / 19 | 41 / 33 | 77 / 23 |
| 0.90 | 49 / 15 | 80 / 19 | 34 / 23 | 71 / 20 |

`MIN_CONFIDENCE` stays 0.8. (READS-dev.md's older Tesseract table, 48 / 121 right, predates later
harness changes, which is why both readers were re-run rather than compared against it.)

The contour numbers above are for `readLabelCrop`'s path, which passes `{ detectorBoxes: true }`
(read box by box, unpadded). Reading those crops the way bands are read (padded, one line per row)
scored 72 / 27 on heldout2 at 0.8, so contour labels keep the detector's boxes.

Case 13, the benchmark through the shipped `readText` (`plottracer-benchmarks/harness/score-ocr.mjs`,
unchanged, PMC splits 4 and 5, 12,751 horizontal tick labels):

| reader | exact |
|---|---|
| Tesseract (2.6.0) | 10,169 (79.8%) |
| PP-OCRv6 tiny recognition alone, on the same crops | 11,423 (89.6%) |
| shipped reader, first port (detector boxes, unpadded) | 10,186 (79.9%) |
| shipped reader, final (padded, one line per row) | 11,540 (90.5%) |

What it took to get from the first port to the final one, all measured on 2,000 of those labels:
the detector found nothing in tight crops (text touching the border), fixed by laying white paper
of half the short side round the region (1,570 to 1,661 right); and on a tight crop it cut
neighbouring ink (a tick, a bar edge) into boxes of its own and read them as `1` or `.`, fixed by
reading a single detected row as one line (1,735 right).

⚠️ The padding is guarded by this benchmark only. A single-label test was tried three ways
(synthetic, synthetic with JPEG and an axis tick, and a crop from the article's own CC BY figure)
and each one read correctly WITHOUT the padding too: the gain is statistical across thousands of
labels, and no one crop reproduced it. The corpus cannot ship in this repository, so re-run the
benchmark after any change to `electron-ocr-paddle.cjs`.

Other findings in the build, each fixed and explained where the code is:
- The resize had to match OpenCV's to the unit: a float resize split one detector blob and lost
  6 px of a box, which turned `18 20 22 24` into `1820 2224`.
- PaddleX turns tall boxes a quarter turn before reading them; PlotTracer measures angles itself,
  and with the turn the axis vote chose 90 degrees for upright labels, so the turn is gone.
- The recogniser writes no space between widely spaced labels on one line (`AprMayJunJul`); a gap
  over 1.15 line heights now ends a word.
- `℃`, `℉`, the Kelvin and Ångström signs are spelled out as the characters a person types.
- onnxruntime-web's wasm computes on the calling thread, so the engine runs in a worker thread.

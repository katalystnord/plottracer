# v2.7: Automatic graph detection (beta), part 1: the graph type

Status: design, written before any code, for David to agree. Branch `v2.7-figure-type`.
Workflow decided by David on 2026-10-16. The research behind it, with every number below:
`plottracer-ref/research/v2.7-figclass/FINDINGS.md`.

## Why

David, 2026-10-16: vision should eventually suggest the graph type, find calibration points and tick
marks together with PlotTracer's own tools, and find the legend; it must be shippable and should run on
ONNX. This is the first of those. The tick and legend half is a separate, later piece of work
(`plottracer-ref/research/v2.7-figdet/FINDINGS.md`): PlotTracer's own tick finder (`algorithms/axisTicks.ts`)
finds 43% of the ticks on 1,267 real figures, where a trained detector found 88%.

Measured on 536 real figures from openly licensed papers, each checked by eye
(gallery: https://claude.ai/artifact/5Wpp1v5j1t7rbCGBgLjLxF):

| | this design | Docling's model alone |
|---|---|---|
| handled types suggested right | 277 / 324 | 265 / 324 |
| wrong suggestions | 17 | 21 |
| heatmaps named | 14 / 33 | 0 / 33 |
| unhandled types declined | 133 / 212 | 129 / 212 |

The types it suggests are the six that make up about 90% of published figures by count: XY, Bar,
Box plot, Pie, Map, Heatmap. Every other figure gets "no type suggested".

## The workflow (agreed with David, 2026-10-16)

- Nothing automatic happens when a figure is opened. **The user captures and crops the figure first.**
- Once a figure is captured, the calibration card offers a button: **Automatic graph detection (beta)**.
  All automatic reading starts from that button and never before it. Today it suggests the graph type;
  the detector work later adds tick marks, calibration points and the legend behind the same button.
- The suggestion is an OFFER (tenet 9): the graph type does not change until the user accepts it.
- When nothing is suggested, the card says so in one line.
- The button stays after calibration has started. Accepting a different type then warns before work is
  discarded, through the same route the Graph type picker already uses (`changeAxesType` and
  `confirmDiscardIfDirty` in `Workspace.tsx`), which keeps the captured figure and keeps a calibration
  the two types share.
- No confidence number is shown. Only suggestions above the cutoff appear, so a suggestion already means
  "confident".

## How other tools ask for the type (tenet 11, swept 2026-10-16, after the workflow was settled)

| tool | how the type is chosen | anything automatic |
|---|---|---|
| WebPlotDigitizer (v5) | a "Select Axes Type" dialog after loading: 2D XY, Bar Chart, Polar, Ternary, Map (Scale Bar), Image, Circular Chart Recorder; calibration follows | "AI Assist (Experimental)": a separate panel, "Click run to attempt auto-generating Axes and Datasets", with a usage quota; the backend is proprietary and server side. No type suggestion found. |
| plotdigitizer.com | a graph-type control in the top menu; "XY, which is the default selection" | rule-based autotracing (Pro); no type detection found |
| Engauge | Cartesian by default; Settings > Coords before digitizing for polar or log | none for the type |
| LabPlot (Data Extractor) | "select the plot type (Cartesian, polar, etc.)" after import, before the reference points | none for the type |
| StarryDigitizer, plotextract | XY only, nothing to choose | |
| Excel, Recommended Charts | a separate entry point: ranked suggestions with live previews, the user picks one, an "All Charts" tab beside it | suggestions only, never applied silently |

Sources: automeris.io/docs/digitize; WebPlotDigitizer v5 app text read from a third-party mirror
(webplotdigitizer.bose.dev), not the official site; plotdigitizer.com/docs and its tutorial; the Engauge
user manual (Coordinates dialog); LabPlot's 2.2.0 release notes and docs.labplot.org; Excel tutorials
(no official Microsoft page was found).

What it says about this design:
- **No digitizer found suggests the graph type.** Every one asks for it before calibration, most with XY as
  the default; PlotTracer's picker already works that way and stays as it is.
- **The closest prior art is WebPlotDigitizer's AI Assist, and it has the same shape David chose:** a
  separate, explicitly labelled experimental feature that does nothing until the user presses run. Two
  differences are deliberate: it GENERATES axes and datasets, where this OFFERS a type (tenet 9); and it
  runs on a remote server with a quota, where this runs offline on the user's machine (a key constraint).
- **Excel never applies a suggestion either;** the user picks, and the full list stays beside it. Excel
  ranks several suggestions; this offers one, because only suggestions above the cutoff are shown.

## Shape of the change

- **Two ONNX files**, about 16 MB each, shipped beside the OCR models:
  - Docling's DocumentFigureClassifier v2.5 (EfficientNet-B0, MIT), unchanged: splits a chart into XY, bar,
    box plot, pie, map.
  - PlotTracer's own fine-tune of the same network on generated figures: chart / heatmap / other.
  - Fused with fixed logit shifts (other -3.0, heatmap -1.5) and one cutoff (0.7), all chosen on PMC
    split-1 'select' only. The fusion is a few lines and is the only logic; both files are read as they are.
- **Runtime:** onnxruntime-web (wasm) in a worker thread in the main process, about 36 ms per figure on
  CPU. ⚑ REUSE: the OCR already runs onnxruntime-web in its own worker (`ui/electron-ocr-worker.cjs`);
  the build first checks whether that worker can host these sessions too, before adding a second one.
- **Input:** the captured crop as PNG bytes, the same thing `readText` takes, decoded by the existing
  `electron-ocr-png.cjs`. Preprocessing: squash to 224 x 224, bilinear, ImageNet mean, Docling's std.
- **On screen:** a button and an offer line on the calibration card, decided in
  `engine/calibrationCardModel.ts` (where the card's decisions live, so they are unit-testable) and
  rendered by the card. Accepting calls the picker's own `onChange` path.
- **Attribution:** README and Help > About name Docling's DocumentFigureClassifier v2.5 (MIT) and say
  PlotTracer ships a fine-tuned copy; the MIT licence text ships in the package. The copyright holder is
  read from the model repository's own licence at build time, not assumed.
- **Model files are reproducible:** the fine-tune is rebuilt by `plottracer-ref/research/v2.7-figclass`
  (`setup.sh`, `gen.py`, `train.py --scheme gate`, `export.py`, `calib.py`); the build records the files'
  sha256.

## Cases (each a named test, written red before the code)

Card and workflow:
1. Given no figure is captured, the calibration card shows no Automatic graph detection button.
2. Given a captured figure, the card shows the button, and nothing has been read: no model has run.
3. Given the button pressed on a captured heatmap, the card offers Heatmap with a button to use it, and
   the Graph type still shows the type it had.
4. Given that offer accepted, the Graph type is Heatmap, the captured figure is unchanged, and the card
   shows the first calibration step.
5. Given the suggestion is the type already selected, the card says the figure looks like that type and
   that it is selected, with nothing to accept.
6. Given the button pressed on a captured spider chart, the card shows one line saying no type was
   suggested, and the Graph type is unchanged.
7. Given calibration points already placed, accepting a different suggested type asks before discarding
   them, and declining leaves the type, the figure and the points as they were.
8. Given a new figure captured, an offer made for the previous figure is no longer shown.

Reader:
9. Given the network removed, the reader answers for a bundled sample (offline, like the OCR's case 1).
10. Reading a figure leaves no file anywhere on disk.
11. Given bytes that are not an image, the answer is a refusal sentence and the process lives.
12. Given a read that cannot finish in time, the answer is a refusal sentence, not a hang.
13. The bundled samples get the answers measured in research: spider, polar, ternary, contour,
    candlestick and circular chart get no suggestion, and each handled-type sample gets the answer the
    research run gave it (copied from that run when the test is written; it is not 29 of 29).
14. The shipped reader, run on the 536-figure real set, reproduces the research numbers above
    (a benchmark run like OCR case 13, outside the repository's own test suite: the set cannot ship).

Package:
15. The packaged app suggests a type for a bundled sample (`packagedApp.e2e.test.ts`).
16. Help > About and README name the model and its MIT licence, and the licence text is in the package.

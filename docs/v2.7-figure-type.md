# v2.7: Automatic graph extraction (beta)

Status: design, written before any code, for David to agree. Branch `v2.7-figure-type`.
Workflow decided by David on 2026-10-16, in conversation. The research behind it, with every number
below: `plottracer-ref/research/v2.7-figclass/FINDINGS.md` (graph type) and
`plottracer-ref/research/v2.7-figdet/FINDINGS.md` (tick marks, labels, legend).

## Why

David, 2026-10-16: vision should suggest the graph type, find calibration points and tick marks together
with PlotTracer's own tools, and find the legend; it must be shippable and should run on ONNX.

Today there is no real transition between capturing a figure and choosing its graph type: the moment a
figure is captured, the calibration card opens with whatever type was last used. This design adds that
transition, and behind it a second, automatic way through the figure, while the manual way stays as it is.

The graph-type suggestion, measured on 536 real figures from openly licensed papers, each checked by eye
(gallery: https://claude.ai/artifact/5Wpp1v5j1t7rbCGBgLjLxF):

| | this design | Docling's model alone |
|---|---|---|
| handled types suggested right | 277 / 324 | 265 / 324 |
| wrong suggestions | 17 | 21 |
| heatmaps named | 14 / 33 | 0 / 33 |
| unhandled types declined | 133 / 212 | 129 / 212 |

It suggests the six types that make up about 90% of published figures by count: XY, Bar, Box plot, Pie,
Map, Heatmap.

## The workflow (agreed with David, 2026-10-16)

**Opening and capturing are unchanged.** The user opens an image, captures and crops the figure.

**Then a choice card, in the calibration card's place:**
- **Try automatic graph extraction (beta)**
- **Go to manual guided extraction**

**Manual** is today's workflow, unchanged, with one addition: under "Calibration" the calibration card
says, in italics, *Start by selecting the appropriate graph type.*

**Automatic** is a chain of steps, one card each:
- Every automatic card has **[< Previous] [Next >]**. Nothing is read or extracted until the user presses
  Next, so the user can follow what happens. Previous undoes the last step and goes back one card.
- Every automatic card has **Leave automatic extraction** in its top left. It drops the user into the
  manual guided path and keeps everything that has been accepted up to that point: the captured figure,
  set axis points, set tick marks and so on. (Changed by David, 2026-10-16; it first removed everything.)
- A **guide window** floats over the canvas and helps the user through each step. Each step places it
  where it covers neither that step's card nor the part of the figure the step is about; for the first
  step, the lower right corner. The user can drag it, and fold it.

The steps:
1. **Graph type.** The full graph type card opens out (every type shown). If the model suggests a type,
   that type is marked in green. The user always clicks a type, whether it is marked or not; a suggestion
   is never accepted for them.
2. **If the clicked type has no automatic workflow yet,** an apology card says so and offers the manual
   guided path with that type selected. This happens right after the type is clicked, before any
   automatic step has run.
3. **Axes.** The label-read offer (`LabelAxesOffer`, V5-V10) for every kind of figure: a drawn PDF as
   today; a picture (PNG, JPEG, scan) through the chart-element detector built in this work, with
   PaddleOCR reading the labels. The same card, the same pairing of each label with its own tick mark, the
   same refusals.
4. **Data.** The type's existing automatic reader, run on Next: Find lines or By colour for XY and Map,
   bar detection for Bar and Histogram, the grid and Read cells for Heatmap; Places to check lists what it
   was unsure of.
5. Then the existing series, output and export cards.

## The cards (designed one by one with David)

**Card 1, the choice card** (agreed 2026-10-16), in the calibration card's place right after capture:

```
┌─ Graph extraction ─────────────────────────┐
│                                            │
│  [ Try automatic graph extraction (beta) ] │
│  [ Go to manual guided extraction        ] │
│                                            │
└────────────────────────────────────────────┘
```

Title "Graph extraction"; the two buttons stacked, full card width, equal weight; no other text.

**Step 1, graph type** (David, 2026-10-16):
- The full Graph type card opens, exactly as it is today. The only difference: a type identified with at
  least 70% confidence (the cutoff the measurements used) is highlighted in green.
- A new, separate card in the lower right corner of the canvas: a [Leave automatic extraction] button in
  its top left, and a guiding instruction in the middle, something like "Please select graph type".
  No Previous or Next on this card.

**Every new card is a step guide card** (David, 2026-10-16): it appears once, during its own step, and
closes when that step ends.

**The apology card** (David, 2026-10-16): if the user clicks a graph type that has no automatic extraction
yet, the Graph type card closes and a new card appears in the centre of the canvas area:
- "Apologies, but we have not yet implemented an automatic extraction for this graph type."
- Below it, two buttons: [Back to graph type selection] [Continue with manual guided extraction].
- The back button is there because the user may have clicked the wrong graph type.

**The axes card** (David, 2026-10-16): if the user clicks a supported graph type, a card that looks very
similar to today's calibration card, top to bottom:
1. [Leave automatic extraction mode], top left.
2. Today's header, unchanged: ▼ Calibration · 0/4 set · [Reset calibration].
3. A [Read graph axis] button.
4. An [Accept suggested graph axis] button, greyed out at first.
5. An italic line: *Select an axis point to adjust it.*
6. [< Previous] [Next >].

Open (David): should Next stay greyed out until the user accepts the points? Next may be superfluous on
this card, but may be kept for consistency. To be seen.

Not on this card: Common origin, Log X, Log Y, Skip rotation. (Log X and Log Y are set by the read itself,
V9; Common origin only saves a click in the manual walk; Skip rotation stays at its default.)

**The cards after calibration** (David, 2026-10-16): the same pattern as the axes card, one card each, in
this order:

*Tick marks / categories:*
1. [Leave automatic extraction mode], top left.
2. Today's "Categories" header from the calibration card's second stage, unchanged.
3. [Read tick marks / categories].
4. [Accept suggested tick marks / categories], greyed out at first.
5. *Select a tick mark or category to adjust it.*
6. [< Previous] [Next >].

*Legend:*
1. [Leave automatic extraction mode], top left.
2. A "Legend" header (no legend card exists today to reuse).
3. [Read legend].
4. [Accept suggested legend], greyed out at first.
5. *Select the legend box to adjust it.*
6. [< Previous] [Next >].

*Extracting series:*
1. [Leave automatic extraction mode], top left.
2. A "Series" header.
3. [Extract series]: the type's existing reader (Find lines, bar detection, Read cells).
4. [Accept extracted series], greyed out at first.
5. *Select a series to adjust it.* Today's Places to check list sits below this line for anything the
   reader was unsure of.
6. [< Previous] [Next >].

Machinery (David: "we do not have the machinery in place for all of these things to work yet"): the
series readers exist; the tick-mark, category and legend reads for pictures need the chart-element
detector built in this work; the axis read exists for drawn PDFs and needs the detector for pictures.

## How other tools ask for the type (tenet 11, swept 2026-10-16)

| tool | how the type is chosen | anything automatic |
|---|---|---|
| WebPlotDigitizer (v5) | a "Select Axes Type" dialog after loading: 2D XY, Bar Chart, Polar, Ternary, Map (Scale Bar), Image, Circular Chart Recorder; calibration follows | "AI Assist (Experimental)": a separate panel, "Click run to attempt auto-generating Axes and Datasets", with a usage quota; the backend is proprietary and server side. No type suggestion found. |
| plotdigitizer.com | a graph-type control in the top menu; "XY, which is the default selection" | rule-based autotracing (Pro); no type detection found |
| Engauge | Cartesian by default; Settings > Coords before digitizing for polar or log | none for the type |
| LabPlot (Data Extractor) | "select the plot type (Cartesian, polar, etc.)" after import, before the reference points | none for the type |
| StarryDigitizer, plotextract | XY only, nothing to choose | |
| Excel, Recommended Charts | a separate entry point: ranked suggestions with live previews, the user picks one, an "All Charts" tab beside it | suggestions only, never applied silently |

Sources: automeris.io/docs/digitize; WebPlotDigitizer v5 app text read from a third-party mirror
(webplotdigitizer.bose.dev), not the official site; plotdigitizer.com/docs and its tutorial; the Engauge
user manual (Coordinates dialog); LabPlot's 2.2.0 release notes and docs.labplot.org; Excel tutorials
(no official Microsoft page was found).

What it says about this design:
- **No digitizer found suggests the graph type;** every one asks for it before calibration. The manual
  path keeps doing exactly that.
- **The closest prior art is WebPlotDigitizer's AI Assist,** a separate, opt-in, explicitly experimental
  path that does nothing until the user presses run, which is the shape of the automatic path here. Two
  differences are deliberate: it generates axes and datasets in one go, where here every step is offered
  and confirmed with Next (tenet 9); and it runs on a remote server with a quota, where this runs offline
  on the user's machine.
- **Excel never applies a suggestion either;** the user picks, and the full list stays beside it.

## Shape of the change, reusing what exists

- **Graph type suggestion:** two ONNX files, about 16 MB each, shipped beside the OCR models:
  Docling's DocumentFigureClassifier v2.5 (EfficientNet-B0, MIT), unchanged, and PlotTracer's own
  fine-tune of the same network (chart / heatmap / other), fused with fixed logit shifts (other -3.0,
  heatmap -1.5) and one cutoff (0.7), all chosen on PMC split-1 'select' only. About 36 ms per figure on
  CPU, onnxruntime-web (wasm) in a worker thread; the build first checks whether the OCR's worker
  (`ui/electron-ocr-worker.cjs`) can host these sessions before adding another. Input is the captured
  crop as PNG bytes, as `readText` takes.
- **The type card:** the existing `GraphTypeCardPicker` grid, so the suggestion is seen in the same place
  as the choice it refers to. The suggested type is marked green; green gets its own colour in
  `ui/theme.ts` (the theme has no green yet; a selected card is teal). Clicking a type goes through the picker's own path (`changeAxesType`).
- **Axes:** `engine/labelCalibration.ts` and `LabelAxesOffer`, unchanged, given a second source of labels
  and tick marks for pictures: the detector (part 2) plus PaddleOCR.
- **Data:** the existing readers and Places to check, started from the data card's Next.
- **Previous:** each automatic step is one entry in the existing undo history (`history.commit`), so
  Previous is an undo of exactly that entry plus one card back, and it cannot disagree with Ctrl+Z.
- **Guide window wording:** from the same source as the tips bar (`engine/guidanceTip.ts`), so the manual
  tips bar and the automatic guide window cannot contradict each other. The card decisions live in the
  engine (as `calibrationCardModel.ts` does), so they are unit-testable.
- **Licences:** the MIT licence file ships beside the classifier's model files, as `ui/ocr-model/` already
  does for PaddleOCR and ONNX Runtime. Credits in the Help menu are a separate design (below).
- **Model files are reproducible** from `plottracer-ref/research/v2.7-figclass`; the build records their
  sha256.

A fixing release. Nothing new: every change here is a number that was wrong, a
refusal that could not fire, or a message that said the wrong thing.

## Numbers that were wrong

**A figure whose series were captured in different shapes read some of them
incorrectly.** The shared bar table asked for the value names once, off whichever
series was selected, and then read every other series under that same shape. A
series of another shape had its numbers read under a premise it was never
captured under, which is the quiet kind of wrong: the table looked complete.
Every series is now read and headed by its own shape.

**A tilted polar figure could calibrate on a frame that carries no reading.** Two
declared angles a hundredth of a degree apart were accepted, and a figure whose
own radii were 50 and 100 then read 143,264 at a mid-figure pixel. The check
existed and compared against a millionth of a millionth, which is exact
degeneracy and nothing else, so everything short of that passed. It now asks
about the angle between the two directions rather than about a quantity that
carries the size of the figure.

**The same fault, in the guard every other type shares.** X and Y axes one pixel
from parallel calibrated cleanly and amplified every reading. The threshold is
now the angle itself, so the same figure photographed at twice the size gets the
same answer, and a badly distorted scan is still accepted.

**A box plot's Open and Close could be named backwards on an inverted value
axis,** and a stacked segment's typed value is recorded as the height the column
shows.

## Refusals that could not fire, and messages that misled

**A tilted figure with a logarithmic radial axis was told to type the one value
that cannot work.** The origin step asked for the radial value there, "usually
0", on an axis where zero has no logarithm, and the calibration was then refused
with a complaint about values that were all valid numbers. The step now asks for
the innermost ring's value, and says it must be greater than zero.

**A project archive reported nothing when it could not package a figure's
image** - it threw where it had promised to return a refusal, so the save wrote
no file and said nothing. It now says which figure, in words.

**Measurements are checked when they arrive from a file,** to the same standard
as when they are drawn.

**A reopened heatmap answers every question its card asks.** The colour key row
could come back with neither option selected.

**A foreign project opens for what it measured, not for the picture it bundles.**
One importer refused an entire project over a missing or unreadable image while
the others opened it and said so; they now agree, in one sentence.

**The figure picker belongs to the file it was listing,** so a project chosen
from it can no longer be read against a different file opened later.

## Said plainly

**Layered graphs are not supported yet, and PlotTracer now says so.** A project
can arrive holding series of different kinds on one graph - a WebPlotDigitizer
project where one dataset has point groups and another does not. It opens, every
series is read correctly under its own columns, and a line says that layered
graphs are not supported yet. Nothing to press.

**The manual names every graph type that offers category ticks.** It listed four
of the six.

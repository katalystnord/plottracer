The error-bar model rebuilt around the datum that owns it, one click / two clicks
made the same gesture on every output panel, and a re-audit that ran until it
stopped finding things.

## Error bars belong to their datum

An error bar used to be a separate series related to its parent by name, and
which cap belonged to which point was worked out at read time, every time. That
resolution was invisible when it was right and invisible when it was wrong.

**A cap is now a member of its datum's own row.** The four roles - upper, lower,
left, right - are appended to whatever slots the graph type already owns, so an
XY point carries `Value` plus four and a bar carries `Bar start`, `Bar end` plus
four. The tuple says which cap belongs to which reading, so the drawing and the
record cannot disagree: neither of them is inferring anything any more.

**The handle end IS the cap.** There is no separate ball marker to drift away
from the whisker it belongs to, because there are no longer two objects that have
to agree. Caps are always draggable - you no longer have to make a series active
before you can move one.

**The app stops naming the error for you.** The kind of error - SD, SEM, 95% CI -
is printed in the figure's caption, not drawn in its geometry, so we could only
ask you to type it, and asking means offering a default. That name becomes the
export column heading, so an invented one would ride into your file.

**Error bars work on every graph type that has points**, and on the types with a
value axis we can measure - XY, Bar, Box Plot, Histogram, categorical Line - the
cap is pinned to the line its datum's value runs along, so it cannot lean. On the
types whose geometry cannot say, the cap is simply free.

## One click selects, two edit - on every panel

Every output panel now answers a click the same way: **one click selects the row
and rings it on the figure, a double click opens the editor for the fields that
type offers.** Bar, Box Plot, Pie and the histogram's bins could not do the first
half of that at all before - a table of twenty bars could not tell you which bar
on the figure it meant.

The editor now occupies **the value's own box**, so opening one moves nothing
else on screen. Names are click-to-edit rather than permanent input boxes: a
name you are not required to give should not sit there as a field demanding one.

## Which numbers came off the pixels

A value you typed rather than measured now reads in `[square brackets]` on
screen and carries a `<field> source` column into the file. You are not the only
instrument looking at the figure - a hatched cell, an asterisk over a fill, a
label bleeding into the ink - so a reading you take by eye is a reading, recorded
through the same transform as ours. What the record distinguishes is measuring
from inventing, not you from us.

**Where you can type one, in this release: XY charts, spider profiles and
heatmap cells.** On Bar, Box Plot, Histogram and a categorical Line you can name
a category but not type a value, so the bracket mark and its `source` column
cannot appear there. That is a capability those types have not been given yet
rather than a mark that has gone missing, and it is the piece the v2.4 label
reading needs before it can offer you a printed number to accept.

## A categorical Line measures its category

A Line on a categorical axis stored a value and worked out its category from
left-to-right capture order. Capture a figure whose second category has no point
and every later point silently moved up one. It now sits on a banded axis and its
category is the band its own pixel falls in - a function of that pixel and the
calibration and of nothing else, which is what lets a plotting library place it.

## The Trace Challenge

The bundled examples ship ground truth, and the Trace Challenge scores a trace
against it. It is a way to find out how good you are at this, and a way for us to
find out where the tool makes it hard.

## An eye-dropper, alongside colour as a measurement

Colour became something this release measures, and a plain eye-dropper came with
it. Pick it up in the Measure tool, click a pixel, and it records the colour it
read - and where a colour key is calibrated, the value that colour stands for.
It is a convenience, not a new instrument to learn: a reading you could otherwise
only take by eye, written into the same measurements block as distance, angle,
area and slope.

## Smaller, and the re-audit

The calibration prompt no longer vanishes at the moment it is needed. A reused
corner stops telling you to click it again. The heatmap card stops saying one
thing three times. A file action that fails says so instead of looking like it
worked; cancelling an export no longer marks your work saved.

Then the release was audited twice - once by hand, once by a fleet - and forty
findings were fixed before the tag. The ones worth naming, because they were
wrong in the FILE rather than on the screen:

- a stacked or grouped **bar chart** valued every series but one by the wrong
  rule, and which one was right depended on what was selected when you pressed
  Export;
- one error cap on a **spider** chart dropped every reading but the first spoke
  from all nine export formats, while the panel went on showing them all;
- **error columns** reached the tables and not the JSON on bar, box plot and pie,
  and reached nothing at all on the histogram;
- a **figure switch** carried the previous figure's heatmap grid and hand-taken
  readings into the next figure's record;
- the **colour key** was sampled once and reused against the next figure's image.

A project file's tuple positions are now bounded at the load door, a typo in a
colour box is refused instead of quietly meaning black, and a series name from
someone else's file can no longer reach a spreadsheet as a formula.

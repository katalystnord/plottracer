PlotTracer can now read a figure's category names off the figure, so the most
tedious typing in a bar chart is a single drag; and the download is smaller than
v2.3.0 was, despite carrying an OCR engine.

⚠️ **This release is still in progress.** What follows is what is built and
driven so far, written as it lands rather than assembled the night of the tag -
which is the whole reason this file is checked before a version can be tagged.

## Read the category names instead of typing them

Calibrate a bar chart and the Categories card offers **Read labels from the
figure**. Drag one box round the row of labels under the axis, and every category
name comes back at once.

**The box is cut up by the axis you already marked.** It is never read as one
strip - that does not work, and it was measured not working: a whole axis in one
box came back as `30 20 ) V 5 10`, while the same numbers read perfectly one tick
at a time. So the band is divided at the category axis's own boundaries, one
region per category, and each is read on its own. Each half of that comes from
whoever actually knows: you can see where the labels are printed, and the axis
knows where one category ends and the next begins.

**Nothing is written until you say so.** The readings arrive in an offer window
with one row per category, and **each row shows the pixels it read** beside the
name it made of them, with the reader's confidence. Correct anything wrong, then
Apply. A row you leave empty is left alone - an empty reading means "nothing was
read", never "erase this name". Because every name that reaches the record has
been read and approved by a person, an OCR'd name is not marked or treated
differently from a typed one: there is nothing left to distinguish.

**Labels printed sideways are handled, and you can see that they are.** Every
region is read at all four quarter turns, and the *axis* decides which way its
labels are written rather than each label deciding for itself - which matters,
because on a test figure the per-label answer was confidently wrong about one
label in six, while the axis was right about all six. Any row can still be turned
by hand with `Rotate`: the picture in that row turns with it, and the name
underneath changes, so you can see what the reader is looking at.

## It works offline, like everything else here

The OCR engine and its English data are **bundled in the app**. No part of a
figure, and no request of any kind, leaves the machine to read a label - and that
is tested rather than asserted: the test removes the network functions outright
and the labels still read.

## A smaller download than v2.3.0, with OCR added

| | v2.3.0 | v2.4.0 |
|---|---|---|
| Linux `.deb` | 106.3 MB | **93.2 MB** |
| Linux AppImage | 139.4 MB | **119.8 MB** |

Every release up to now shipped about 107 MB of library code that nothing in the
app could reach: the interface's own libraries are compiled into the application
bundle, and a copy of each was being packaged beside it as well. They are gone.
The app is now driven **as a packaged binary** by its own test before release, so
the missing-file class of fault that this kind of change risks is caught here
rather than by you.

## Also in this release

- **A point keeps its number** when its series carries no error caps: the figure
  and the table were counting different things, so a datum labelled `19` on the
  figure could be `7` in the panel.
- **An inactive series no longer draws fatter than the active one**, where it
  covered the very ink it was traced from.
- **A selected error cap is drawn as a bar**, along its own tick, because a cap
  is a bar - not ringed with a circle borrowed from a data point.
- **The shared-origin answer belongs to the figure you answered it about**, and
  no longer follows you to the next one.
- **A bar's value can be typed**, and typing it moves the bar along its value
  axis rather than overwriting a number - the same rule every other type follows.
- **Tick marks a figure draws can be found** on an axis you have already marked
  (groundwork: a second opinion on your calibration, coming in a later release).

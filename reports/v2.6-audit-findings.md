# v2.6 pre-release audit - findings and status

Five reviewers, 2026-10-10, each on one area of `git diff master...v2.6`:
algorithms, record/model, workflow (Parallel Universe David), exports and
tenets, tests. Findings merged where two reviewers found the same thing.
Status: OPEN, FIXED (commit), or DECIDED (not a defect, with the reason).

## Critical

- **A1. Line edits strip per-point metadata** (record + exports + workflow,
  three reviewers, proved). `getLinePoints` kept only bridged/shared, so Cut,
  Join, Move, the Eraser box, Del across lines and closing a hand-drawn line
  rewrote a Guide-points line with no anchor/interpolated roles: spline
  points exported as measured, became draggable, `Point` column vanished.
  Reaches plain XY via the Eraser box.
- **A2. Select + Del on XY deletes points not selected** (workflow, traced;
  test pinned it). The cross-line removal split a series at every removed
  stretch and dropped any one-point leftover: deleting the middle of three
  hand-placed points removed all three; one outlier split a scatter in two.
  Also: erasing part of a closed ring left two lines (exports, proved).

## High

- **B1. Select catches nothing on an XY series with error bars** (workflow).
  `selectAcrossLines` returned true with an empty selection for a slotted
  series, so the old path never ran. Worked before v2.6. Cut then says
  "Click ON a line" while the user is clicking on it.
- **B2. Undo / figure switch during label reading writes the wrong state**
  (workflow). Lines added, then OCR awaited per label, then label reads and a
  commit applied to whatever state is current.
- **B3. Masks do not move with rotate / crop** (workflow). `notDataRegions`
  not mapped by image edits: Find lines then bridges across the wrong area.
- **B4. `uncross` splits a closed contour into two open lines** (algorithms,
  proved).
- **B5. `unspiral` closes a loop with a straight chord marked measured**
  (algorithms, proved): up to 90 px of invented geometry, role measured, no
  gap recorded.
- **B6. `sampleInkRgb` returns paper or a neighbour** (algorithms, proved):
  middle of a 6 px line -> white; a blue line 2 px from a black frame ->
  black.
- **B7. Find lines blocks the UI ~18 s on 3000x3000** (algorithms, measured):
  all raster work over the whole image, on the UI thread.
- **B8. Colour-key levels rounded to a fixed 4 significant figures** (exports):
  a key 10000-10010 gives every line 10000; the comment claims otherwise.
- **B9. Tests that cannot fail** (tests): K1's e2e check is skipped when the
  list is empty (it is, on the bundled example); F3's bound is inside the
  frame; F4/S2 never compare a bridge with the line it fills; K6 (one Undo)
  is promised on screen and untested; F5 (CORE) never compared with truth.

## Medium

- **C1. "Find lines again" deletes corrected lines and keeps cut pieces**
  (exports + workflow): replacement by remembered NAME removes lines whose
  level was typed or used from the label, and keeps pieces that took new
  names.
- **C2. Places, Find lines memory and notices survive undo/redo and figure
  switches**, and a comment claims they are cleared (workflow, gate 3).
- **C3. Selections go stale after Join and after clicking a place**
  (workflow).
- **C4. Move moves only the active line's share of a cross-line selection**
  while every selected point is ringed (workflow, mirroring).
- **C5. Contour colour key skips the heatmap key's guards** (record, proved):
  four key clicks on one pixel calibrate without error.
- **C6. Log level accepts 0 and negative typed levels** (record, proved).
- **C7. The "most decimals" rule turns one bad read into the only accepted
  one, and refuses every whole number on `%g` labels** (algorithms, proved).
- **C8. Gaps closed by closeLoops/unspiral are not in `gaps`**, so their label
  slot is never read (algorithms, reasoned).
- **C9. Aliased clean rings split, with fake label specks** (algorithms,
  proved). Reported as places, not silent.
- **C10. Interpolated levels go stale** when a neighbour's level changes
  (exports, reasoned).
- **C11. Cases doc out of date**: S2 says bridged exports as `interpolated`
  (it is `bridged`); F8 says hand-drawn lines stay open (C3 now closes them).

## Low

- D1. Join clears an error relation pointing at the removed line instead of
  moving it; pieces copy whole-line metadata (curve fit, label read, error
  relation) (record).
- D2. `setNotDataRegions` accepts NaN x/y (record).
- D3. Log axis "uneven" message shows log10 values (algorithms).
- D4. No-passing rule applied to contours only; comment says always
  (algorithms).
- D5. `keyPositionOfColour` max distance 45 is twice the neighbour spacing
  (algorithms).
- D6. `ownInkResidual` does not clamp the box to the image (algorithms).
- D7. Cut mode survives undo across a type change; Eraser disabled when the
  active line is empty although its box acts on every line (workflow).
- D8. Join with on XY scatter invents bridged points between scatters
  (workflow).
- D9. Place texts carry line names from creation time (workflow).
- D10. Stale comments: exportAssembly Point/Level-from, contourLevel source
  list, quoted numbers no test enforces (exports).
- D11. Per-line label rule written again inline instead of `levelsFromReads`
  (exports, reuse).
